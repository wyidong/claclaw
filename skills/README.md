# claclaw 技能规范

写给做 claclaw 技能的人和 AI。新技能照这里做，旧技能改动时顺手对齐。
示例看 `claw-tv`（最规整）；几个技能共用一套代码的看影音组（`claw-video` 等 + `_lib/media/`）。

## 1. 技能是什么

一个技能 = 一份给 AI 看的说明（SKILL.md）+ 一个命令（`<名>.mjs`）+ 事先核对好的数据（`*.json`）。

- **AI 只做三件事**：听懂用户要什么、跑命令、把输出原样贴给用户。
- **命令负责其余的一切**：找、筛、去重、排序、核对能不能用。

这样换成 DeepSeek、Kimi 这类模型也能用好，结果的好坏不靠模型发挥。

## 2. 目录和命名

```
skills/
  index.json              技能登记表（claclaw 按它安装、显示）
  _lib/<名>/              几个技能共用的代码（不是技能，不登记、不安装）
  claw-<名>/
    SKILL.md              必有
    <名>.mjs              命令入口（文件名 = 技能名去掉 claw-），没有命令的技能可以不要
    *.json                事先核对好的数据（平台表、频道表……）
    *.mjs                 其他模块（来源适配 sources.mjs 等）
```

- **命令入口**：claclaw 启动时生成 `~/.claclaw/bin/claw-<名>`（Windows 再生成一个 `.cmd`），用 claclaw 自己的 node 跑。AI 的终端里不一定有 node。
- **依赖**：只用 Node 内置模块和系统自带的 `curl`，不 `npm install`。外部工具（yt-dlp、ffmpeg）用到时再下载到 `~/.claclaw/tools/`。
- **缓存和状态**：放 `~/.claclaw/<名>/`，不写进技能目录。各 Claw 用的是复制件，claclaw 启动时会用仓库里的版本覆盖。
- **登记**：在 `index.json` 加一条，字段是 `name`、`title`、`desc`、`group`、`scene`、`claws`、`auto`。
  - `group`：技能大组，技能页按它分组显示。现有「通用」（interconnect、file、theme）、「影音」（video、music、audio、movie、image、tv）。
  - `claws`：默认写全部会跑命令的 Claw（claude deepseek opencode kimi qwen codex openclaw glm iflow minimax codebuddy qoder copilot gemini）。写成空的 `[]` 就是只给 kuAi 用：不往别家装，技能页也不显示（现在只有 claw-install）。
  - `auto`：默认写全部四个安装位置（claude agents iflow codebuddy），用到哪个 Claw 就自动装到哪。
  - kuAi 不用安装：直接读仓库里的 SKILL.md、用 node 跑命令脚本（找会话、发文件除外），所以命令要能单独跑、输出能原样贴。新技能要在 `skills/kuai.json` 加一条：
    - `brief`：一句话（40 字以内）。能力够的模型拿到的技能清单里只写这一句，完整的说明等它读 SKILL.md 时才给（清单全量列出要一千多 token）。
    - `fill`：给小模型用的「填空」定义。小模型跟不住「自己选技能、自己写命令」，所以由程序按关键词（`when` / `not`）认出用户想用这个技能，模型只把参数（`slots`）填进固定的 JSON，程序校验后按 `args` 拼命令、跑、把输出贴出来。字段说明在 `src/claws/kuai-fill.mjs` 开头；例子（`examples`）里的参数必须是那句话里的原文。输出本身就是给用户看的话、没跑成也要原样说的（装软件），加 `"raw": true`。
    - `ask`（可选）：跑之前要用户在网页上点确认。`true` 是每次都要；写成正则就是参数对上了才要（claw-install：看进度不问，真要装才问）。`askTitle` 是确认条上的问法。会改动这台电脑的技能都要加。
- **同步**：改了 `skills/` 下的文件不用手动重装。claclaw 启动时按内容哈希，把各 Claw 目录里的复制件同步成新版。
- **复制件只给 AI 看 SKILL.md**：命令总是由 `~/.claclaw/bin/` 跑仓库里的脚本，所以脚本可以用相对路径引 `../_lib/`。

## 3. 拆分和分组

- **一个技能管一件事**：用户的说法、命令、回复方式有一样不同，就拆成两个。比如影音拆成视频、纯音频的歌、MV、电影、图片、电视六个，各自的 description 只写自己的说法，AI 一句话就能选对。
- **写清边界**：description 最后一句点名兄弟技能，比如「电影用 claw-movie，听歌用 claw-music」。容易混的说法（「来首歌」算 claw-music 纯音频，「XX 的 MV」算 claw-audio，「纪录片片段」算视频）写进对应技能的说法里。
- **同类放一个大组**：`index.json` 的 `group` 相同。
- **公共代码放 `_lib/<名>/`**：搜索、下载、代理这类几个技能都要的，只写一份。技能自己的 `<名>.mjs` 只做一件事：把自己的命令翻译成公共代码的调用（见 `_lib/media/cli.mjs`）。
- **命令形式统一**：`claw-<名> "关键词"` 是最常用的默认动作；其余动作用第一个词做子命令（`find`、`get`、`related`、`sources`、`list`…），选项用 `--xxx`。
- **改名、拆分**：在 `src/skills.mjs` 的 `RETIRED` 里写「旧名 → 接替的新名」。claclaw 启动时会删掉旧的复制件和命令，在原位置装上新的；用户自己的同名技能不碰。

## 4. SKILL.md 的结构（固定顺序）

```markdown
---
name: claw-<名>
description: <做什么>：用户说「<原话 1>」「<原话 2>」「<原话 3>」时使用。<结果是什么样的>。
---

# <标题>

一段话：做什么、数据从哪来（只用官方 / 有授权的来源）、**只用这个命令，不要自己编**。

## 命令
（代码块：一行一个用法 + 注释；下面一行写 Windows 路径和没有命令时的 node 回退写法）

## 怎么回复
（输出怎么贴、前面写几句话、不要做什么。每条一句，必须做的加粗）

## 说明
（限制和原因：为什么有的东西做不到，免得 AI 去硬试）
```

- **description**：决定 AI 会不会用这个技能。要写 3～6 句用户的原话，让 AI 一句话就能判断该不该用。
- **用词**：中文，祈使句，一条一件事。不写背景故事，不写「可能」「建议」这类含糊的话。
- **场景多的技能**：先考虑拆（见第 3 节）；同一件事的几种做法（比如视频的「直接播」和「下载」）留在一个技能里，按场景分节。

## 5. 输出约定（技能和 claclaw 页面之间的接口）

| 要给用户的东西 | 命令输出 / 回复里怎么写 | claclaw 显示成 |
|---|---|---|
| 能在线播的视频、音频 | `[标题](网址)` | 带 ▶ 的链接，点了在顶上的播放器播 |
| 只放声音（纯音频） | 音频文件直链（.mp3 / .m4a…），或 claclaw 认得的几种：B 站视频网址加 `#audio`、网易云外链 `music.163.com/song/media/outer/url?id=…`、5sing / 酷我歌曲页、Bandcamp 曲目页加 `#audio`、Free-Stock-Music / ccMixter / Incompetech 的 mp3 直链 | 顶上的音频条，没有画面（这几种由服务器 `/api/aud` 转：要来源页或是 http；只转白名单里的站，别的站要转先在 src/audproxy.mjs 登记） |
| 片单 / 列表 | 编号列表 `1. [片名](网址) · 年份 · 类型 · 时长 · 来源` | 一条消息里超过 3 个能播的链接就成为播放列表 |
| 频道 / 入口卡片 | ```` ```tv ```` 块，一行一个：`分组 \| 台标字 \| 名称 \| 网址 \| 说明` | 卡片：能播的带 ▶，其余点了新开页面 |
| 主题卡片 | ```` ```theme ```` 块，一行一个：`主题 id \| 名字 \| 说明` | 卡片：画出那个主题的样子，点了马上换上 |
| 行情卡片 | ```` ```stock ```` 块，一行一条，第一段是种类：`股 \| 名称 \| 代码 \| 板块 \| 现价 \| 涨跌 \| 涨跌幅 \| 时间`、`项 \| 名字 \| 值 \| + 或 - \| 小字`、`势 \| 标题 \| 涨跌幅 \| 说明 \| 收盘价（逗号分开）`、`日 \| …`、`比 \| …`、`注 \| 说明`；板块资金流用 `题 \| 标题 \| 小字`、`段 \| 小标题`、`流 \| 名次 \| 板块 \| 净流入 \| 净占比 \| 涨跌幅 \| 领流入`；排行榜把 `流` 换成 `榜 \| 名次 \| 名称 \| 代码 \| 现价 \| 涨跌幅 \| 成交额 \| 行业 \| 标记` | 卡片：大字现价、一格一个数、走势折线、表（资金流那格垫色条）；红涨绿跌 |
| 文件 | `send_file` 工具，或反引号里写路径 | 文件卡片 / 预览 |

- **stdout**：只放给用户看的内容，AI 原样贴。进度、调试、错误写 stderr。
- **退出码**：0 是有结果，1 是用法错，2 是没找到。
- **给程序用的输出**：加 `--json`（服务器接口会调用，比如 `/api/related`）。
- **新的卡片类型**：在 `public/index.html` 的 `md()` 里给新的代码块语言加一个渲染函数（照 `mdTv` 写），样式写进 `app.css`。旧页面不认识这种块时会显示成代码块，也要看得懂，所以一行一条、字段用 `|` 分开。

## 6. 数据和来源

- **只用官方、有授权或公版的来源**。不用盗版，不绕过 DRM、登录、地区限制和签名。做不到的老实写进「说明」。
- **先平台，再内容**：数据按平台（来源）组织，每个平台下面挂它的内容（`platforms.json`）。
  - 同一个内容可能在几个平台都有，用**同一个名字**合并。
  - 结果每个平台一条，能在 claclaw 里直接播的排在前面。
- **事先核对好的放 JSON**，随仓库更新，每条核对过才放进去。
- **会变的用的时候现查**，比如正在直播哪一场、最新上传了什么。现查失败就用存的那条，并标上「可能没在播」。
- **出墙的来源走代理**：优先 `--proxy`，其次环境变量，最后本机的 7890 / 7897 端口。
- **要快**：来源并发查，结果缓存约 30 分钟，元数据长期缓存。常见请求控制在几秒以内，慢就是要优化的地方。
- **中文优先**：claclaw 的用户以华人为主，推荐和排序都先给中文内容。

## 7. 多 Claw

- 不要依赖 Claude 专属的工具。用到 `send_file` 这类工具时，写清楚没有它的 Claw 该怎么做。
- 命令路径统一写 `~/.claclaw/bin/claw-<名>`，各 Claw 都能跑。

## 8. 验收（提交前）

1. 用几句典型的说法真跑一遍：`node skills/claw-<名>/<名>.mjs …`。
2. 纯逻辑（匹配、解析）写 `test/<名>.test.mjs`，跑 `npm test`。
3. 改了页面显示：
   - 起一个临时实例：`HOME=<临时目录> CLACLAW_DATA=<临时目录> CLACLAW_HOST=127.0.0.1 node server.mjs --port 8799`，在临时 HOME 的 `.claude/projects` 里放一个假会话。
   - 用无头浏览器截图，看电脑、手机、深色三种情况。
   - 不碰线上实例，不开有界面的浏览器。
4. `npm run check && npm test` 通过，私密串检查结果为 0。
