# claclaw 群聊 设计

日期：2026-11-03　状态：用户已确认（第一版先做出来试）

## 为什么做
用户同时用 3 个会话协作一个需求：15 上 1 个（整理需求），本机 2 个（后端、前端）。三方的话分散在三个会话里，用户要来回切换着看进度、回答问题、在它们之间转述。群聊让三方的对话集中到一处：用户一句话可以同时交代给几个会话，会话之间对接口也在群里进行、用户顺带看到。

## 目标
- 一处看全：成员的回复（包括成员之间互相说的）都显示在群里。
- 少转述：用户 @ 一个或几个成员下指令；成员回复里 @ 别的成员，claclaw 自动转过去。
- 成员可以是本机任意 Claw 的任意会话，也可以是已配对电脑（协同）开放给本机的会话。

## 不做（第一版）
- 不 @ 时自动分派（调度模型）。
- 群列表、群历史归档：群建好放在「最近」里，从「最近」删掉 = 解散，记录一起删除。
- 成员同时改同一份代码的协调。
- 逐字流式显示成员回复。

## 反目标（做成这样算失败）
- 一条消息让所有成员各跑一轮（没 @ 也触发）——费额度、抢答。
- 成员之间无限互相 @，AI 对聊停不下来。
- 群把成员会话搞坏：成员会话本身照常可在 claclaw 里单独打开、单独对话。

## 用户已经定的
1. **入口**：「最近」页搜索框左边让出一个和会话 logo 等宽的位置，放「建群」按钮（现在搜索框左边是 #tmpTh，右边是新建会话 #sNew；建群按钮放在搜索框左侧）。
2. **建群选成员**：可以选本机和协同的任意 Claw 的任意会话。本机会话显示对应 Claw 的 logo + 会话名；协同会话显示它的 Claw logo + 协同标识（两个同时展示）+ 会话名；对方没给出 Claw 时只显示协同标识。
3. **群放在「最近」里**，和会话一起按最近活动排序；从「最近」删除 = 解散群。
4. **拉了协同会话的群，对方电脑的「最近」里也自动出现这个群**：在对方 claclaw 里打开能看到同样的群聊、也能在里面发消息。群的主体（记录、投递、@ 转发）仍在建群的电脑上，对方那边是镜像：建群电脑把群的变化推过去，对方发的消息转回建群电脑处理。任何一边删除 = 解散，两边都消失。
5. **其他按建议**（见下）。

## 规则（按建议，用户认可）
- **必须 @ 才触发**：@ 谁谁回一轮；@全体 = 所有成员都回。输入 @ 弹出成员列表，按会话名选。
- **没 @ 的消息只记录**：不触发任何成员。某成员下次被 @ 时，把它上次被投递之后的群消息（带说话人）一起带上，最多最近 20 条。
- **成员互相 @**：成员回复里出现 @某成员 → 转给那个成员（同样带上它没看过的群消息）。一条用户消息引出的转发最多 2 跳；成员不能 @ 自己；超过 2 跳的 @ 只显示、不转发，群里提示「已到转发上限」。
- **投递格式**：沿用现有协同消息的格式和投递通道（本机走 peerDeliver(local)，协同走 peerCall），开头标明「claclaw 群聊「群名」· 来自 X」，正文是这段群记录 + 本条。成员的这一轮回复自动贴回群里。
- **成员在忙**：排队（沿用现有排队/重发），群里显示「X 在忙，排队中」，送到后照常贴回。
- **协同成员事后回复（202）**：对方先回 202、回复稍后单独发回时，要能落回群里（群需要一个可被 from_session 指向的编号；注意对方会把 from_session 里 [\w-] 以外的字符去掉）。
- **授权确认**：成员要用户确认操作时，确认仍在它自己的会话里做；群里显示「X 在等你确认」，点击跳到那个会话。
- **推送 / 未读**：以群为单位计未读、推送；用户正在看这个群（页面可见且打开的就是它）时不计未读、不推送（与会话一致，含 clarelay 外壳的 visible）。

## 权限与边界（实现者问到后补的决定，标【我定】的是 Claude 的判断，用户可改）
- **用户 @ 的消息 = 用户本人的指令**【我定】：投递给成员时等同于用户在那个会话里直接打字，不加「对方只能提需求、不能指挥」那层说明，不设 peerTurn（不额外要确认）。开头只标明「claclaw 群聊「群名」· 用户」和附带的群记录。
- **成员 @ 成员的转发 = 现有会话间消息**【我定】：沿用现在的说明和 peerTurn（只能提需求、有风险的操作要用户确认），和成员用 peer_send 互发一样。
- **成员之间不要绕开群**【我定】：投递说明里写「找本群其他成员请在回复里 @ 它，不要用 peer_send」；不拦截 peer_send（绕开了就不进群，可接受）。
- **群在协同权限里的位置**【我定，只收不放】：
  - 发出：群是用户自己建的，向协同成员发消息不要求「发起会话加入协同池」，但目标仍只能是对方开放给本机的会话（规矩不变）。
  - 收回：群只接收「对自己发出的消息的回复」（reply_to 是群发过的 msg_id），不出现在给对方看的会话列表里；对方会话和本机其他会话都不能主动往群里发消息。
- **长度**【我定】：单次投递总长不超过现有上限 4000 字。本条消息原样保留；附带的群记录从最旧的开始逐条截短（每条最多约 300 字）或丢弃，直到放得下。不放宽两边的上限。
- **两台电脑一起改**【我定】：15 跑的是同一个仓库，push 后 15 pull 重启即可，协议改动两边同时上线。对方是旧版本时：协同成员的「等你确认」提示和跳转、对方那边的推送合并都降级（不显示 / 照旧推），其余照常。

## 群里显示
- 像普通聊天：用户的消息靠右；成员的消息靠左，带 Claw logo（协同成员用协同图标）和会话名。
- 成员回复中显示「X 正在回复…」，回完整条出现。
- 群标题默认用成员名拼起来，可改名（沿用会话改名）。

## 约束
- 单进程 Node：server.mjs + 前端单文件 public/index.html；协同在 peer.mjs。改动集中在这三处。
- 协同的权限规矩不变：只能找对方开放给本机的会话；对方发来的消息只按它说的那件事处理。
- 不输出、不外传密码令牌；群记录存 data/ 下（已 gitignore）。
- 提交前 npm run check && npm test。
